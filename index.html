Codex Goal & Claude Code /goal

긴 작업을 끝까지 추적하는 Goal 기능 가이드

Codex와 Claude Code의 goal 기능을 사용자 관점에서 설명하고, 실제로 어떤 목표 문장을 써야 하는지 예시와 함께 정리했습니다.

Codex부터 보기 차이점 비교

Short version

Goal은 “다음에 무엇을 할지”와 “언제 끝났는지”를 계속 붙잡는 장치입니다.

일반 프롬프트는 한 번의 요청에 가깝지만, goal은 긴 작업의 완료 조건을 세션에 붙여 둡니다. 그래서 에이전트가 여러 단계의 조사, 수정, 검증을 반복하면서도 원래 성공 조건을 잊지 않도록 돕습니다.

  • 잘 맞는 작업마이그레이션, 테스트 통과까지의 버그 수정, 문서 사이트 완성, 이슈 백로그 처리처럼 완료 조건을 검증할 수 있는 일.
  • 덜 맞는 작업단순 질문, 한 줄 명령, 아직 성공 기준이 불명확한 아이디어 탐색. 이 경우 먼저 계획을 세운 뒤 goal로 바꾸는 편이 낫습니다.

Codex

Codex Goal mode 사용법

OpenAI Codex 문서에 따르면 Goal mode는 긴 작업 동안 Codex가 계속 추적할 “지속적인 목표”를 설정하는 기능입니다. goal 텍스트는 시작 프롬프트이자 완료 기준으로 쓰이며, Codex app, IDE extension, CLI에서 /goal로 시작할 수 있습니다.

CLI에서 설정하기

/goal Finish the migration and keep tests green

현재 goal을 보려면 인자 없이 /goal을 입력합니다. 일시정지, 재개, 삭제는 각각 /goal pause, /goal resume, /goal clear를 사용합니다.

활성화가 안 보일 때

[features]
goals = true

/goal이 slash command 목록에 없으면 config.toml에서 features.goals를 켜거나 CLI에서 codex features enable goals를 실행합니다.

이 세션의 Codex API 도구 기준

현재 API 세션에는 goal을 직접 다루는 도구도 노출됩니다. 사용자에게 일반적으로 보여 줄 문서에서는 slash command 중심으로 설명하면 되고, 자동화나 내부 세션 추적을 설명할 때는 아래처럼 구분하면 됩니다.

도구 역할 주의점
create_goal 사용자가 명시적으로 요청한 목표를 새로 등록합니다. 에이전트가 임의로 만들면 안 됩니다.
get_goal 현재 목표, 상태, 시간 및 토큰 사용량을 확인합니다. 진행 상황 점검용입니다.
update_goal 목표가 실제로 완료되었거나 엄격히 막혔을 때 상태를 바꿉니다. complete는 검증 후에만, blocked는 같은 차단 조건이 반복될 때만 사용합니다.
작성 팁: “리팩터링해줘”보다 “결제 모듈을 TypeScript strict 모드로 마이그레이션하고 npm test와 npm run lint가 모두 0으로 끝나게 해줘”처럼 검증 방법을 같이 적는 편이 좋습니다.

Claude Code

Claude Code의 /goal

Claude Code 공식 문서의 /goal은 “완료 조건”을 설정하면 Claude가 여러 턴에 걸쳐 조건이 충족될 때까지 계속 작업하는 기능입니다. 문서 기준으로 Claude Code v2.1.139 이상이 필요합니다.

기본 사용

/goal all tests in test/auth pass and the lint step is clean

이미 goal이 있으면 새 조건이 기존 goal을 대체합니다. 인자 없이 /goal을 실행하면 현재 상태, 실행 시간, 평가된 턴 수, 토큰 사용량, 평가자의 최근 이유를 확인할 수 있습니다.

비대화형 실행

claude -p "/goal CHANGELOG.md has an entry for every PR merged this week"

Claude Code 문서는 -p와 함께 goal을 설정하면 한 번의 호출 안에서 완료까지 루프를 실행할 수 있다고 설명합니다. 중단은 Ctrl+C로 합니다.

Claude의 평가 방식

Claude Code는 각 턴이 끝난 뒤 별도의 빠른 소형 모델이 조건 충족 여부를 예/아니오로 평가합니다. 이 평가자는 도구를 직접 실행하지 않으므로, 테스트 결과나 파일 변경 요약처럼 Claude가 대화에 드러낸 증거를 기준으로 판단합니다.

요구 조건

공식 문서에 따르면 /goal은 신뢰된 workspace에서만 동작하며, hooks 시스템을 사용합니다. hooks가 관리 정책으로 비활성화된 경우에는 사용할 수 없습니다.

Comparison

Codex와 Claude goal 비교

항목 Codex Goal mode Claude Code /goal
핵심 개념 긴 작업 동안 붙잡을 지속적인 objective와 완료 기준 완료 조건을 만족할 때까지 턴을 이어 가는 세션 goal
시작 명령 /goal <objective> /goal <condition>
상태 확인 /goal, app의 progress row, 또는 세션 goal API /goal
중단과 정리 /goal pause, /goal resume, /goal clear /goal clear, stop, cancel 등 clear alias
좋은 조건 결과, 측정 가능한 목표, 테스트 기준 포함 평가자가 대화 기록에서 확인할 수 있는 측정 가능한 조건
길이 제한 CLI 문서 기준 objective는 1자 이상 4,000자 이하 공식 문서 기준 condition은 최대 4,000자

Examples

바로 쓸 수 있는 goal 문장

문서 사이트 배포

/goal Codex와 Claude의 goal 기능을 설명하는 정적 문서 사이트를 만들고, GitHub Pages에서 접근 가능한 URL까지 확인해줘.

테스트 기반 버그 수정

/goal 로그인 리다이렉트 버그를 수정하고 npm test와 npm run lint가 모두 성공하게 해줘. 인증 흐름 외 파일은 바꾸지 마.

마이그레이션

/goal 결제 모듈을 새 API로 마이그레이션하고 모든 call site가 컴파일되며 기존 결제 테스트가 통과하게 해줘.

좋은 goal 체크리스트

  • 완료 상태무엇이 끝나야 하는지 한 문장으로 적습니다.
  • 검증 방법테스트, 빌드, 파일 수, 배포 URL, 이슈 개수처럼 확인 가능한 증거를 붙입니다.
  • 제약 조건건드리면 안 되는 파일, 유지해야 하는 API, 시간 또는 턴 제한이 있으면 함께 적습니다.
