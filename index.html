Codex Goal & Claude Code /goal

Goal은 긴 작업을 끝까지 붙잡는 장치입니다.

한 번의 질문이 아니라, 완료 조건을 세션에 묶어 두고 조사, 수정, 검증을 반복하도록 만드는 발표용 요약입니다.

화살표 키, 스페이스, 화면 버튼으로 슬라이드를 넘길 수 있습니다.

Why it matters

문서형 요청은 쉽게 흩어지고, Goal은 완료 기준을 계속 끌고 갑니다.

마이그레이션, 테스트 통과, 배포 확인처럼 끝 상태가 중요한 작업에서 특히 유용합니다.

1 요청작업의 목적과 완료 조건을 선언
2 분해파일, 명령, 검증 방법으로 나눔
3 반복조사와 수정을 여러 턴에 걸쳐 유지
4 완료증거가 있을 때만 목표 달성으로 판단

Codex

Codex Goal mode는 작업의 성공 조건을 세션에 고정합니다.

  • ACLI, 앱, IDE에서 시작/goal로 목표를 설정하거나 현재 상태를 확인합니다.
  • B진행 상태 추적목표, 상태, 사용량, 남은 예산을 기준으로 작업을 이어 갑니다.
  • C검증 후 완료완료 증거가 부족하면 목표를 좁히지 않고 계속 진행합니다.

Claude Code

Claude Code의 /goal도 완료 조건 중심으로 작업을 지속합니다.

조건을 세우면 여러 턴에 걸쳐 그 조건을 만족하려고 진행하며, 상태 확인과 정리 명령으로 관리합니다.

/goal all tests in test/auth pass and the lint step is clean
claude -p "/goal CHANGELOG.md has an entry for every PR merged this week"
/ 조건 입력명령 한 줄로 완료 기준을 지정
? 상태 확인현재 목표와 평가 이유를 확인
x 정리필요할 때 goal을 clear
✓ 완료 판단검증 가능한 조건을 만족할 때 종료

Comparison

핵심 차이는 표현보다 운영 방식에 있습니다.

둘 다 “끝까지 할 일”을 붙잡지만, Codex는 현재 세션의 작업 목표와 검증 감사에 더 초점을 둡니다.

Codex Goal mode

  • 명시적인 objective를 세션에 등록
  • /goal pause, resume, clear로 관리
  • 완료 전 요구사항별 증거 확인을 강조

Claude Code /goal

  • 완료 조건을 명령으로 지정
  • 상태 조회와 clear 흐름 제공
  • 조건 충족 여부를 평가하며 반복 작업

Prompt patterns

좋은 goal은 결과, 검증, 제약을 한 문장 안에 둡니다.

결과가 분명한가 검증할 수 있는가 건드리면 안 될 것이 있는가
문서 사이트 배포

/goal Goal 기능 설명 사이트를 만들고 GitHub Pages URL에서 접근 가능한지 확인해줘.

테스트 기반 수정

/goal 로그인 리다이렉트 버그를 고치고 npm test와 npm run lint가 모두 성공하게 해줘.

마이그레이션

/goal 결제 모듈을 새 API로 옮기고 기존 결제 테스트가 통과하게 해줘.
